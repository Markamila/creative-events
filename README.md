# Сайт студии творческих мероприятий

Витрина услуг, пакеты и цены, галерея, анкета-заявка с сохранением в PostgreSQL, уведомление менеджера (Telegram и/или e-mail) и закрытая админ-панель.

**Стек:** Node.js 22 · Express · PostgreSQL · чистые HTML/CSS/JS (без сборки) · Docker.

## Быстрый старт (Docker)

```bash
cp .env.example .env
# заполните в .env минимум: JWT_SECRET (openssl rand -hex 32) и ADMIN_PASSWORD (от 10 символов)
docker compose up --build
```

- Сайт: http://localhost:3000
- Админка: http://localhost:3000/admin (логин `admin` и пароль из `ADMIN_PASSWORD`)

База и демо-контент (услуги, три пакета, галерея, FAQ) создаются автоматически при первом запуске. Данные хранятся в томе `pgdata`.

## Деплой на Render

1. Загрузите папку в GitHub-репозиторий.
2. Render → **New → Blueprint** → выберите репозиторий. Файл `render.yaml` создаст веб-сервис (Docker) и базу PostgreSQL и свяжет их.
3. Render спросит значения секретных переменных: обязательно `ADMIN_PASSWORD`, `PUBLIC_URL` (адрес вида `https://название.onrender.com`), остальное можно заполнить позже. `JWT_SECRET` сгенерируется сам.
4. После деплоя откройте `/admin`, войдите и смените пароль (вкладка «Аккаунт»).

> **Для боевого сайта** смените тарифы в `render.yaml`. На бесплатном тарифе сервис «засыпает» без трафика (первое открытие ~30–60 с), а бесплатная база Render ограничена по сроку жизни. Для бизнеса нужны платные тарифы веб-сервиса и базы.
>
> Фотографии из админки хранятся **в базе данных**, а не на диске, поэтому не пропадают при перезапусках и деплоях (диск Render временный). Бэкапы базы — по тарифу Render или через `pg_dump`.

## Что требует ваших аккаунтов

Всё остальное работает сразу. Без этих настроек заявки всё равно сохраняются и видны в `/admin`, но менеджер не получает мгновенного уведомления.

| Интеграция | Что нужно | Переменные |
|---|---|---|
| **Telegram** (рекомендуется) | Бот от @BotFather и chat id | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` |
| **E-mail** | Любой SMTP (Gmail с паролем приложения, Яндекс, Brevo…) | `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, `MANAGER_EMAIL` |
| **Соцсети, телефон** | Ваши аккаунты | вводятся в `/admin` → «Сайт и контакты» |
| **Домен** | Свой домен (необязательно) | Render → Settings → Custom Domains, затем обновить `PUBLIC_URL` |

**Подключение Telegram:** `@BotFather` → `/newbot` → токен. Откройте бота и нажмите Start (или добавьте в группу менеджеров). Chat id: напишите `@userinfobot` либо откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `chat.id`. Вкладка «Уведомления» в админке содержит ту же инструкцию и кнопку **«Отправить тестовое уведомление»**.

## Что редактируется в админке

Вкладки `/admin`: **Заявки** (статусы из ТЗ, внутренние комментарии, поиск, экспорт CSV) · **Услуги** (добавить, изменить, скрыть, удалить, фото и примеры работ) · **Пакеты и цены** (цена «от», за участника, за группу или по запросу) · **Галерея** (загрузка и удаление фото) · **FAQ** · **Сайт и контакты** (название, тексты, телефон, WhatsApp, Telegram, Instagram, город, часы работы, примечание о ценах, SEO) · **Уведомления** · **Аккаунт**.

## Фото и иллюстрации

Сейчас вместо фотографий стоят **стилизованные пастельные иллюстрации-заглушки** (папка `public/img`, генерируются `npm run art`). Реальных фото ваших работ у меня нет, поэтому замените их через админку: «Галерея» → «Загрузить фото», «Услуги» → «Изменить» → фото, «Сайт и контакты» → главное фото. Название компании (по умолчанию «Pastel Studio»), демо-цены, телефон и ссылки на соцсети тоже заменяются в админке.

## Безопасность

- Пароли — bcrypt; сессия — подписанный JWT в `HttpOnly`, `SameSite=Strict`, `Secure` (в production) cookie на 12 часов; ограничение попыток входа.
- Защита от CSRF в админке (обязательный заголовок для изменяющих запросов), заголовки helmet и строгая CSP.
- Заявки: серверная валидация, лимит запросов по IP, невидимое поле-ловушка для ботов, подписанный токен формы (мгновенные отправки отклоняются), защита от дублей, обязательное согласие на обработку персональных данных (момент согласия сохраняется).
- Загружаемые фото проверяются по содержимому (SVG и прочее отклоняются), перекодируются в WebP и сжимаются.
- Весь пользовательский текст выводится как текст, а не как HTML (XSS).
- Текст политики обработки данных в окне на сайте — шаблон. **Перед запуском согласуйте его с юристом** под законодательство вашей страны.

## Разработка и тесты

```bash
npm install
export DATABASE_URL=postgres://user:pass@localhost:5432/db ADMIN_PASSWORD=TestPass12345 JWT_SECRET=dev NODE_ENV=development
npm start        # http://localhost:3000
npm test         # сквозные тесты на реальной PostgreSQL (меняют данные — используйте отдельную базу!)
```

## Структура

```
src/            сервер: маршруты, база, валидация, уведомления, демо-данные
public/         сайт (index.html, css, js), админка (admin/), иллюстрации (img/)
scripts/        генератор иллюстраций
test/           сквозные тесты
Dockerfile · docker-compose.yml · render.yaml · .env.example
```
